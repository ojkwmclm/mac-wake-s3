# v0.5.1 第一阶段业务监督（2026-10-29）

基线：3f194e8（v0.5，仅点灯云端控制）。当前阶段只观察业务故障，不添加业务 TWDT 订阅，不调用 esp_restart，不改变 USB 描述符或远程唤醒信号实现。保留原有 IDF 中断看门狗 300ms、双核 Idle TWDT 60s 及 panic 重启。默认配置显式记录这些值以及实机基线已开启的 Shift；不再依赖以前私有构建配置的隐式遗留。

## 改动

- 释放债务与请求 busy 分离。一次请求结束后清除 busy，保留零报告释放债务；有债务时禁止新的睡眠/Shift 按下，但允许 USB Remote Wakeup 请求。
- 零报告提交成功不再等同释放完成；由 HID 完成回调确认传输完成。此确认不代表 macOS 睡眠/远程桌面在线。所有按下/释放输入报告共用 armed 门闩，等待上一个回调后才复用端点；mount/unmount 更新连接代次并清除旧传输。
- USB suspend 时保留释放债务，不累计活动总线等待时间。活动状态累计等待 5 秒后仅标记 recovery_required；这个预算是降级/告警策略，不是已实测的硬件死机判据，不会自动重新识别 USB 或重启。已提交但缺失回调的释放会单独标记 inflight_timeout；不能证明旧传输结束时不强行重发，仅保留债务供诊断/人工恢复。
- 发送失败从调用返回时刻安排 1.5、3、6、12、24、30 秒重试，上限 30 秒；成功后恢复 1.5 秒最小发送间隔。沿用 QoS0，发送函数成功不等于 broker 已确认。
- IP 判断同时检查 Wi-Fi 关联。断网走原有重连，不触发整板重启。
- health 任务每秒检查任务阶段/心跳，USB 20 秒、按键 5 秒、云端循环/退避 45 秒，同步认证/发送/停止调用 120 秒为观察告警预算。网络整段阻塞上界尚未证明，120 秒不用于复位，正式阈值需实机测量。
- APP 状态附带 health：firmware、boot_id、seq、uptime_s、reset_reason、supervisor=warn_only、stale_tasks 位图（USB=1、按键=2、云端=4）、release_mask（键盘=1、媒体=2）、release_timeout 、inflight_timeout、usb_epoch、usb_mounted 和 usb_suspended。boot_id 每次启动随机生成，无 NVS 心跳写入。

监督边界：任务心跳不证明 TinyUSB/MQTT 内部任务健康。USB 释放状态单独观察；没有 HID 活动或 MQTT 离线本身不判为死机。未启用新的业务重启，因而尚未实施其复位风暴计数/限额。原有硬件看门狗仍可能复位，不应声称本版本已经解决所有死机。

## 本地验证与实机边界

运行 `IDF_PATH=/实际/esp-idf bash tools/test-cloud-command.sh` 和 `bash tools/test-recovery-policy.sh`；ESP-IDF v5.4.2 构建。策略测试覆盖长睡、活动预算、未完成/失败传输、按下与释放串行、连接代次、断开和退避。暂不能替代 USB 时序/并发与实机验收。

实机保持单根原生 USB：先空闲 3 分钟，观察 boot_id；测试 APP 睡眠→普通键盘唤醒→APP 再睡眠→APP 唤醒，再重复一轮。记录每次状态、boot_id、uptime 是否连续、release_mask 是否在恢复后清零。再测试适度连续点击、路由器断网及恢复、数小时睡眠；每组分开，出现异常不要先复位以免丢失现场。

下一阶段需在独立测试固件中注入业务任务暂停/无进展，验证 supervisor 能发现而不误报正常等待；对 CPU 不让出和中断停滞独立验证原生 WDT。完成最长阻塞测量及验收后，才考虑接入有状态的 TWDT user handle 和受限业务恢复/复位。不得用后台无条件喂狗掩盖故障。

尚不能由应用层无参数回调证明全部物理重枚举竞态；当前依赖固定 TinyUSB 的 USB 任务 FIFO/回调串行处理语义，host 模拟只验证策略，不等同实机时序证明。正式版本前还需单线反复睡醒和断开重接实测。
